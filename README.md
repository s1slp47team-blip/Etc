## 폴더 규칙

새 프로그램을 추가할 때는 **루트에 파일을 그냥 두지 말고 프로그램마다 폴더를 하나씩 만듭니다.**

```
Etc/
├── README.md              ← 이 파일 (프로그램 목록)
├── .gitignore             ← 모든 프로그램에 공통으로 적용되는 무시 규칙
├── render.yaml            ← 배포 설정 (Render Blueprint)
└── <프로그램-이름>/
    ├── <메인 파일>
    ├── requirements.txt   ← 이 프로그램만의 의존성
    └── README.md          ← 실행법, 필요한 환경변수
```

기준은 하나입니다 — **폴더 하나만 열면 그 프로그램을 돌리는 데 필요한 게 전부 그 안에 있을 것.**

- 의존성은 프로그램별 `requirements.txt`에 각각 적습니다. 루트에 공용으로 두지 않습니다.
- 폴더 이름은 소문자 + 하이픈(`food-briefing`)으로 씁니다.
- 30줄짜리 일회성 스크립트처럼 폴더를 만들 만큼이 아닌 것들은 `scripts/` 하나를 만들어 몰아둡니다.
- 여러 프로그램이 같은 코드를 쓰게 되면 `common/` 폴더로 빼냅니다.

## 배포

`render.yaml`에 Render 배포 설정(빌드·실행 명령, 필요한 환경변수 목록)이 들어 있습니다. **폴더 구조를 바꾸면 이 파일의 경로도 같이 고쳐야 합니다** — 예전에 `requirements.txt`를 옮기고 빌드 명령을 안 고쳐서 배포가 깨진 적이 있습니다.

비밀값(API 키·암호)은 저장소에 두지 않습니다. `sync: false`로 "이 변수를 쓴다"는 사실만 남기고 값은 Render 대시보드에서 넣습니다.
