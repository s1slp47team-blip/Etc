# 맛집 브리핑 웹앱

동네 이름을 입력하면 주변 음식점을 모아 **사진 · 대표 메뉴 · 가격대 · 블로그 반응**을 한 표로 보여주는 웹앱입니다.

## 동작 방식

1. 카카오 주소/키워드 검색으로 동네 좌표를 찾습니다.
2. 반경 1km(500m~3km 조절) 이내 음식점을 선별합니다. 기본 20곳이고 10~100곳으로 조절할 수 있습니다 — 가게마다 상세·블로그 조회가 붙으므로 개수가 곧 대기 시간입니다.
   - 카카오 검색은 질의당 45건 제한 → 여러 검색어를 병합해 최대 100곳까지 확보
   - 시간대 선택: **점심**(식사 위주, 술집·안주 전문 제외) / **저녁**(술 동반 업종 + 술집 검색 병합)
3. **가게 목록 카드를 먼저 그립니다.** 사진·별점·영업시간·메뉴는 그 뒤에 구간을 나눠 채웁니다 — 상세 조회를 기다리느라 빈 화면을 보지 않도록.
4. 가게별로 카카오맵 상세(메뉴판·가격·대표 사진·별점)와 카카오(다음) 블로그 후기를 수집합니다.
5. Gemini가 메뉴판과 블로그를 근거로 대표 메뉴 / 가격대 / 블로그 반응을 요약합니다.

> 별점·메뉴판·사진은 카카오맵 상세 페이지의 비공식 내부 API에서 가져옵니다. 이 경로는 한꺼번에 몰아 부르면 막히므로, 막히면 호출 간격을 늘리고 잘 통과하면 도로 줄이면서 다시 시도합니다(여유 있는 시간대에는 간격이 0으로 수렴해 그대로 빠릅니다). 끝내 막히면 별점·메뉴판 없이 블로그 요약만으로 동작합니다.
>
> 검색 결과는 서버가 떠 있는 동안 메모리에 캐시됩니다 (같은 동네를 다시 검색하면 즉시 표시).

## 화면

**검색 전 첫 화면** — 가운데 검색창과 시간대(전체/점심/저녁/카페) 선택, 그리고 네이버지도에 저장해 둔 내 맛집이 사진 카드 8장으로 깔립니다. 고르는 기준은 **폴더별로 번갈아 뽑되 매번 다시 섞는 것**입니다 — 목록 앞에서 그냥 자르면 첫 폴더가 화면을 독식하고 늘 같은 가게만 보입니다. 다만 사진을 이미 받아둔 가게를 앞세워, 화면을 열 때마다 조회가 붙지 않게 합니다(캐시가 차면 전체에서 고르게 섞입니다). 반경·업종·개수·인증·평점 같은 상세 조건은 `＋상세 필터` 뒤로 접혀 있고, 접힌 상태에서도 현재 설정값이 칩에 표시됩니다. 검색한 동네는 브라우저에 기억해 칩으로 다시 꺼내 쓸 수 있습니다(서버로 보내지 않습니다).

**모바일** — 상세 필터는 하단 `필터` 버튼 → 바텀시트로 열리고, 검색 버튼은 하단에 고정됩니다. 저장 맛집은 가로 캐러셀, 결과 카드는 사진이 위로 올라간 세로형입니다.

구형 브라우저(IE 모드)에서도 동작해야 해서 **CSS 변수와 `position: sticky`는 쓰지 않고, 스크립트는 ES5 문법만** 씁니다.

## 실행

```bash
pip install -r requirements.txt
python food_briefing_app.py
```

- 기본 포트는 **8767**이고, 실행하면 `http://localhost:8767`이 자동으로 열립니다.
- 브라우저 자동 실행을 끄려면 `--no-browser` 옵션 또는 `NO_BROWSER=1`.
- 저장소 루트에서 실행할 때는 경로를 붙여주세요: `python food-briefing/food_briefing_app.py`

## 환경변수

| 이름 | 필수 | 용도 |
|------|------|------|
| `KAKAO_REST_API_KEY` | **필수** | 카카오 장소·블로그 검색 |
| `GEMINI_API_KEY` | 권장 | 블로그·메뉴 요약. 없으면 카카오맵 메뉴판 기준으로만 표시 |
| `GROQ_API_KEY` | 선택 | Gemini 무료 한도 소진 시 폴백. 없으면 폴백 생략 |
| `KAKAO_JS_KEY` | 선택 | 지도 표시용. 없으면 지도 버튼만 비활성 |
| `APP_PASSWORD` | 선택 | 설정하면 로그인해야 사용 가능. 외부 공개 인스턴스에서 API 한도 도용 방지용 |
| `PORT` | 선택 | 클라우드(PaaS) 배포 시 지정. 지정하면 `0.0.0.0`에 바인딩합니다 |
| `NO_BROWSER` | 선택 | `1`이면 브라우저 자동 실행 안 함 |

Windows에서는 환경변수가 프로세스에 없으면 사용자 레지스트리(`HKCU\Environment`)에서도 찾습니다. 재로그인 전에 등록한 값도 바로 잡힙니다.

## 배포 시 주의

이 앱이 폴더 안으로 옮겨졌으므로, 호스팅 서비스의 start command도 경로를 포함하도록 바꿔야 합니다.

```
python food-briefing/food_briefing_app.py
```

의존성 설치 경로도 `food-briefing/requirements.txt`입니다.

## 함께 쓰는 파일

| 파일 | 저장소 포함 | 용도 |
|------|:---:|------|
| `내맛집링크.txt` | O | 네이버지도 저장 리스트 공유 링크 목록. 한 줄에 하나씩, `#`로 시작하는 줄은 주석. 환경변수 `MY_PLACE_LINKS`(쉼표/공백 구분)가 설정돼 있으면 그쪽이 우선입니다. 둘 다 없으면 내맛집 기능만 꺼진 채 나머지는 정상 동작합니다. |
| `_인증캐시.json` | X | **실행 중 자동 생성**됩니다. 인증 맛집(미쉐린·블루리본·백년가게·흑백요리사) 조회 결과를 1주일간 보관해 카카오 API 호출을 줄입니다. 지워도 다음 검색 때 다시 만들어지고, 파일을 못 쓰는 환경(읽기 전용 파일시스템)에서는 메모리 캐시만 쓰고 그냥 넘어갑니다. |
| `_홈캐시.json` | X | **실행 중 자동 생성**됩니다. 첫 화면 저장 맛집의 사진·업종을 1주일간 보관합니다. 없으면 첫 화면을 열 때마다 카카오를 다시 부르게 되므로, 지우지 않는 편이 좋습니다. |
| `proxy.txt` | X | **프록시 필수망(사내 백업서버 등)에서만 필요합니다.** 파일에 `http://프록시주소:포트` 한 줄만 넣어두면 `HTTP_PROXY`/`HTTPS_PROXY`로 적용됩니다. 없으면 그냥 건너뛰므로, 일반 인터넷 환경이나 클라우드 배포에서는 만들 필요가 없습니다. |

두 파일 모두 `food_briefing_app.py`와 **같은 폴더**(`food-briefing/`)에서 읽습니다. 다른 위치에 두면 인식되지 않습니다.

## 테스트

API 키 없이 돌아갑니다 (카카오 응답을 가짜로 주입).

```bash
python test_인증호출수.py   # 인증 배지 조회의 카카오 호출 수
python test_첫화면.py       # 첫 화면 저장 맛집 카드 · 캐시 · 템플릿 요소
python test_상세조회.py     # 사진·별점 조회 재시도 · 검색이 상세를 기다리지 않는지
```

인증 배지 조회가 검색 1회당 카카오 호출의 대부분을 차지하던 부분이라, 리팩터링으로 호출이 다시 늘어나지 않는지 수치로 지킵니다.

| 조건 | 카카오 키워드 검색 호출 |
|---|---:|
| 기본 검색 (`cert=none`), 캐시 없음 | 16회 (인증 13 + 일반 3) |
| 인증 필터 (`cert=any` / 개별 인증) | 13회 |
| 같은 격자·반경 재검색 | 3회 (인증 조회 없음) |
| 프로세스 재시작 후 (파일 캐시 사용) | 3회 |

`test_첫화면.py`는 첫 화면이 API를 반복해 부르지 않는지(재시작 후 0회), 저장 리스트가 없을 때 영역이 숨는지, 그리고 화면 스크립트가 쓰는 요소 id가 템플릿에 다 있는지를 확인합니다.
